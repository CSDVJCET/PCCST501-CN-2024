Module 1 Questions (Application Layer)

Solution:

  • Non-Persistent HTTP (HTTP/1.0): Opens a dedicated TCP connection for every single referenced object. Time overhead per object = $2 \times RTT + \text{File Transmission Time}$. High connection setup overhead.
  • Persistent HTTP (HTTP/1.1): Reuses an already established TCP connection for multiple sequential or pipelined requests, eliminating redundant 3-way handshakes and TCP slow-start phases.

Model Answer:

BitTorrent is a decentralized peer-to-peer file-sharing protocol that achieves high upload self-scalability by decomposing files into discrete chunks (pieces, typically 256 KB).

Core Architectural Elements:
  1. Torrent File (.torrent): Contains tracker URLs and SHA-1 cryptographic hashes of all pieces.
  2. Tracker: Central/distributed directory service returning dynamic peer contact lists to joining leechers.
  3. Rarest-First Piece Selection: Peers query neighbors for bitfields and download the rarest pieces first, ensuring maximum availability.
  4. Tit-for-Tat Choking Algorithm: Peers upload preferentially to the top 4 fastest providers, with periodic Optimistic Unchoking (every 30s) to discover new high-speed nodes.

Module 2 Questions (Transport & Network Layer)

Solution:

  • Upon receiving 3 Duplicate ACKs, TCP infers an isolated segment loss rather than catastrophic network congestion.
  • It executes Fast Retransmit (retransmits missing segment immediately without waiting for RTO timer).
  • New Threshold: $\text{ssthresh} = \text{cwnd} / 2$.
  • New Congestion Window: $\text{cwnd} = \text{ssthresh} + 3\text{ MSS}$ (enters Fast Recovery).
