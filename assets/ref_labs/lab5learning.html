What is Network Programming?

Network programming is the process of developing software that enables two or more applications running on different computers to exchange information over a network. Instead of operating only within one computer, these applications communicate through networking protocols such as TCP and UDP.

Examples include:

  • Web Browsers
  • Email Clients
  • Online Banking
  • Video Streaming
  • Cloud Storage
  • Online Games

💡 Key Idea

A socket is simply an endpoint of communication between two applications.

🖥 Client–Server Architecture

Most network applications follow the client–server model. A client is the application that requests a service, while the server provides that service.

Examples include:

Client Server Service

🔌 What is a Socket?

A socket is a communication endpoint used by two applications to exchange data over a network.

Think of a socket as a telephone. A telephone allows two people to communicate. Similarly, a socket allows two programs running on different computers (or on the same computer) to communicate.

Simple Definition

A socket is an endpoint through which a process sends or receives network data.

🎯 Why Does Today's Lab Use TCP?

In today's experiment, the client sends an entire matrix to the server. If even one element of the matrix is lost, the server cannot correctly determine the matrix type. Therefore, TCP is preferred because it provides:

  • Reliable delivery
  • Error checking
  • Correct packet ordering
  • Automatic retransmission
Remember

For programming assignments that require every byte of data to reach the server correctly, TCP is usually the preferred transport protocol.

💻 Socket Programming APIs

A socket program is built by calling a sequence of networking functions provided by the operating system. Every TCP client and server uses these functions to establish communication, exchange data and terminate the connection safely.

① socket()

Purpose

Creates a communication endpoint. This is always the first function used in socket programming.

Syntax

int socket(int domain,
           int type,
           int protocol);

Parameters

Parameter Description
domain Address family (AF_INET)
type SOCK_STREAM for TCP
protocol Normally 0
Returns a socket descriptor. Returns -1 if creation fails.

② bind()

Purpose

Associates the socket with an IP address and a port number. Only servers normally call bind().

Syntax

bind(sockfd,
     (struct sockaddr *)&server,
     sizeof(server));
Think of bind() as assigning an address to your house. Without an address, clients cannot find the server.

③ listen()

Purpose

Places the server socket into listening mode. The server waits for connection requests from clients.

Syntax

listen(sockfd,5);

The second parameter specifies the maximum number of pending connections.

④ accept()

Purpose

Accepts a connection request sent by a client. Once accepted, a new socket descriptor is returned for communication.

Syntax

newsockfd =
accept(sockfd,
       NULL,
       NULL);
The original socket keeps listening. The new socket communicates with one client.

⑤ connect()

Purpose

Used by the client to establish a connection with the server.

Syntax

connect(sockfd,
        (struct sockaddr *)&server,
        sizeof(server));

If the server is not running, connect() fails.

⑥ send()

Purpose

Transfers data from the client to the server or from the server to the client.

Syntax

send(sockfd,
     buffer,
     sizeof(buffer),
     0);

Returns the number of bytes transmitted.

⑦ recv()

Purpose

Receives incoming data from the connected socket.

Syntax

recv(sockfd,
     buffer,
     sizeof(buffer),
     0);
recv() blocks until data arrives unless non-blocking mode is enabled.

⑧ close()

Purpose

Terminates the socket connection and releases system resources.

Syntax

close(sockfd);

Always close sockets after communication finishes.

🎯 API Summary

Function Used By Purpose
socket() Client & Server Create socket
bind() Server Assign IP and Port
listen() Server Wait for clients
accept() Server Accept connection
connect() Client Connect to server
send() Both Transmit data
recv() Both Receive data
close() Both Close socket
Remember the order!

Server: socket → bind → listen → accept → recv → send → close

Client: socket → connect → send → recv → close

Complete TCP Server Program (server.c)

The following TCP server waits for a client connection, receives a message, prints it on the screen and sends back "Hello Client". 


#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>

#define PORT 8080

int main()
{
    int serverSocket, clientSocket;
    struct sockaddr_in serverAddr;
    socklen_t addrSize;

    char buffer[1024];

    /* Create Socket */

    serverSocket = socket(AF_INET, SOCK_STREAM, 0);

    if(serverSocket < 0)
    {
        perror("Socket Creation Failed");
        exit(1);
    }

    printf("Socket Created Successfully...\n");

    /* Server Address */

    serverAddr.sin_family = AF_INET;
    serverAddr.sin_addr.s_addr = INADDR_ANY;
    serverAddr.sin_port = htons(PORT);

    /* Bind */

    if(bind(serverSocket,
            (struct sockaddr*)&serverAddr,
            sizeof(serverAddr)) < 0)
    {
        perror("Bind Failed");
        exit(1);
    }

    printf("Bind Successful...\n");

    /* Listen */

    listen(serverSocket,5);

    printf("Waiting for Client...\n");

    addrSize = sizeof(serverAddr);

    /* Accept */

    clientSocket = accept(serverSocket,
                          NULL,
                          NULL);

    if(clientSocket < 0)
    {
        perror("Accept Failed");
        exit(1);
    }

    printf("Client Connected...\n");

    /* Receive */

    recv(clientSocket,
         buffer,
         sizeof(buffer),
         0);

    printf("Client Says : %s\n",buffer);

    /* Reply */

    strcpy(buffer,"Hello Client");

    send(clientSocket,
         buffer,
         strlen(buffer)+1,
         0);

    printf("Reply Sent...\n");

    close(clientSocket);

    close(serverSocket);

    printf("Connection Closed...\n");

    return 0;
}

Complete TCP Client Program (client.c)

The following TCP client creates a socket, connects to the server, sends the message "Hi Server", receives the server's reply, and displays it on the screen. 


#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#define PORT 8080

int main()
{
    int sockfd;
    struct sockaddr_in serverAddr;

    char buffer[1024];

    /* Create Socket */

    sockfd = socket(AF_INET, SOCK_STREAM, 0);

    if(sockfd < 0)
    {
        perror("Socket Creation Failed");
        exit(1);
    }

    printf("Socket Created Successfully...\n");

    /* Server Address */

    serverAddr.sin_family = AF_INET;
    serverAddr.sin_port = htons(PORT);

    inet_pton(AF_INET,
              "127.0.0.1",
              &serverAddr.sin_addr);

    /* Connect */

    if(connect(sockfd,
               (struct sockaddr *)&serverAddr,
               sizeof(serverAddr)) < 0)
    {
        perror("Connection Failed");
        exit(1);
    }

    printf("Connected to Server...\n");

    /* Read Message */

    printf("Enter Message : ");
    fgets(buffer,sizeof(buffer),stdin);

    /* Send */

    send(sockfd,
         buffer,
         strlen(buffer)+1,
         0);

    printf("Message Sent...\n");

    /* Receive */

    recv(sockfd,
         buffer,
         sizeof(buffer),
         0);

    printf("\nReply from Server : %s\n",
           buffer);

    /* Close */

    close(sockfd);

    printf("Connection Closed...\n");

    return 0;
}

🧪 Lab 5 - TCP Matrix Classifier

In this experiment, a TCP client generates an N × N matrix containing random integers between 1 and 50. The client establishes a TCP connection with the server and sends the matrix. The server receives the matrix, analyzes its structure, and determines whether it is:

  • Diagonal Matrix
  • Upper Triangular Matrix
  • Lower Triangular Matrix
  • None of the Above

Finally, the server sends the result back to the client, which displays the classification.

💡 Understanding the Workflow
  • The client creates a random matrix and establishes a TCP connection.
  • The server waits for incoming connections using listen() and accept().
  • The client sends the matrix order followed by the matrix elements.
  • The server analyzes the received matrix and determines its type.
  • The server sends the classification result back to the client.
  • The client displays the matrix type and closes the connection.

⚙ Server Algorithm

  1. Create TCP socket.
  2. Bind socket to server IP and port.
  3. Listen for incoming connections.
  4. Accept one client connection.
  5. Receive matrix order N.
  6. Receive all matrix elements.
  7. Check the matrix type.
  8. Send the matrix type back to the client.
  9. Close the connection.

💻 Client Algorithm

  1. Create TCP socket.
  2. Connect to the server.
  3. Read matrix order N.
  4. Generate random matrix values.
  5. Display the matrix.
  6. Send N to the server.
  7. Send the matrix.
  8. Receive the classification string.
  9. Display the result.
  10. Close the socket.

🚨 Common Programming Errors

Error Possible Reason Solution
Connection Refused Server not running Start the server first.
Bind Failed Port already in use Choose another port or terminate the previous server.
recv() returns 0 Client disconnected Reconnect the client.
Socket Creation Failed System resource issue Check the return value of socket().
No Response Client and server use different port numbers Verify the port number in both programs.

📋 Programming Checklist

🎯 Programming Tips

  • Always check the return value of socket(), bind(), connect(), and accept().
  • Use the same port number in both the client and the server.
  • Start the server before running the client.
  • Close every socket after communication is complete.
  • Display meaningful error messages using perror().
  • Test your program with different matrix sizes.
