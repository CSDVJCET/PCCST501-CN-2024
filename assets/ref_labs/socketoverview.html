Introduction

Socket Programming enables two applications running on different computers to communicate through a computer network. Every modern Internet application—including web browsers, email clients, cloud platforms, instant messaging systems, video conferencing tools, and IoT devices—relies on sockets for exchanging information.

In Linux and UNIX operating systems, sockets are treated as file descriptors, allowing applications to send and receive data using standard system calls. By understanding socket programming, students gain practical knowledge of how network applications establish connections, exchange messages, and terminate communication.

Learning Outcome After completing this tutorial you will understand the fundamental concepts required to perform TCP and UDP socket programming experiments.

Why Learn Socket Programming?

Web Applications

HTTP, HTTPS, REST APIs and cloud applications use sockets to exchange information.

Communication

Chat applications, email systems and online meetings rely on reliable network communication.

IoT & Embedded Systems

Sensors, smart devices and autonomous systems exchange information using network sockets.

Client–Server Architecture

CLIENT ↓ Creates Request ↓ Internet ↓ SERVER ↓ Processes Request ↓ Returns Response

The client initiates communication by requesting a service. The server waits for requests, processes them and sends back responses. Most Internet applications such as web servers, FTP servers and email servers follow this architecture.

Lab Tip Every TCP programming experiment in this laboratory follows the client–server model.

TCP/IP Protocol Stack

The TCP/IP protocol stack provides a layered architecture that enables communication between applications across interconnected networks. Each layer performs a specific function and offers services to the layer above it.

Layer Main Responsibility Example Protocols
Application Provides network services to user applications. HTTP, FTP, SMTP, DNS
Transport End-to-end communication and reliability. TCP, UDP
Internet Logical addressing and routing. IP, ICMP
Network Access Frame transmission over the physical medium. Ethernet, Wi-Fi
Application ↓ Transport ↓ Internet ↓ Network Access
Exam Tip: Remember the responsibilities of each TCP/IP layer and the protocols associated with them.

Socket Basics

A socket is a communication endpoint used by applications to exchange data over a computer network. Every socket is uniquely identified using three important elements:

IP Address

Identifies the destination device.

Port Number

Identifies the application running on that device.

Transport Protocol

TCP or UDP determines how data is transferred.

Socket = IP Address + Port Number + Transport Protocol

Types of Sockets

Socket Type Protocol Applications
Stream Socket TCP HTTP, FTP, SMTP
Datagram Socket UDP DNS, Streaming
Raw Socket IP Packet analysis, Network monitoring

Socket Address Structures

A socket address structure stores the addressing information required for network communication. It contains the IP address, port number, and address family used by the socket.

sockaddr

Generic socket address structure used by all socket functions.

sockaddr_in

Used specifically for IPv4 socket programming.

sockaddr_in6

Used for IPv6 socket programming.

Application ↓ sockaddr_in ↓ IP Address ↓ Port Number ↓ Operating System

Byte Ordering

Different computer architectures store multi-byte values differently. To ensure compatibility between systems, network applications use a standard format called Network Byte Order, which follows the Big Endian convention.

Type Description
Little Endian Least Significant Byte stored first.
Big Endian Most Significant Byte stored first.
Network Byte Order Standard Big Endian representation used on networks.
Always convert host byte order to network byte order before sending numeric values across the network.

Byte Order Conversion Functions

Function Description
htons() Host to Network Short
htonl() Host to Network Long
ntohs() Network to Host Short
ntohl() Network to Host Long
uint16_t port = htons(8080); uint32_t addr = htonl(ip);

Address Conversion Functions

Applications often need to convert IP addresses between human-readable form and binary representation.

Function Purpose
inet_pton() Convert presentation format to binary.
inet_ntop() Convert binary format to presentation format.
Example
struct sockaddr_in server; inet_pton(AF_INET, "192.168.1.10", &server.sin_addr);

Socket Programming API

The following system calls form the foundation of TCP and UDP socket programming.

socket()

Creates a communication endpoint.

int socket( AF_INET, SOCK_STREAM, 0);

bind()

Associates an IP address and port number with the socket.

bind(sockfd, (struct sockaddr*)&addr, sizeof(addr));

listen()

Marks the socket as a passive socket waiting for incoming client requests.

listen(sockfd,5);

accept()

Accepts a connection request from a client.

accept(sockfd, NULL, NULL);

connect()

Initiates a connection to a remote server.

connect(sockfd, (struct sockaddr*)&server, sizeof(server));

send()

Transmits data to the connected socket.

send(sockfd, buffer, strlen(buffer), 0);

recv()

Receives data from the connected socket.

recv(sockfd, buffer, sizeof(buffer), 0);

close()

Releases the socket and terminates communication.

close(sockfd);
Remember: Server programs generally follow: socket() → bind() → listen() → accept() Client programs generally follow: socket() → connect()

TCP Client Communication Workflow

A TCP client actively establishes a connection with the server before transmitting data.

CLIENT │ socket() ↓ connect() ↓ send() ↓ recv() ↓ close()
Note: The connect() system call automatically performs the TCP three-way handshake before data transfer begins.

TCP Server Communication Workflow

Unlike the client, the server waits for incoming requests and services multiple clients.

SERVER │ socket() ↓ bind() ↓ listen() ↓ accept() ↓ recv() ↓ send() ↓ close()

TCP Connection Establishment

CLIENT SERVER SYN ---------------------> <------------------- SYN + ACK ACK ----------------------> Connection Established

TCP establishes a reliable connection using the famous Three-Way Handshake before transmitting application data.

UDP Communication

UDP is a connectionless protocol. No connection setup or acknowledgement is required.

socket() ↓ sendto() ↓ Network ↓ recvfrom() ↓ close()
UDP is faster than TCP because it does not perform connection establishment, flow control or retransmission.

I/O Multiplexing using select()

The select() system call allows a process to monitor multiple file descriptors simultaneously.

FD_ZERO(&readfds); FD_SET(sockfd,&readfds); select(sockfd+1, &readfds, NULL, NULL, NULL);

Common applications include chat servers, HTTP servers and network monitoring tools.

I/O Multiplexing using poll()

The poll() system call provides an alternative to select() and is more suitable when monitoring a large number of descriptors.

struct pollfd fds[5]; poll(fds, 5, 5000);
