Wireshark Protocol Investigation

🌐 Lab 4: DNS Resolution Detective

Flush cached answers, trigger a fresh DNS lookup, and reconstruct the query–response conversation from packet evidence.

Experiment04
ProtocolDNS
ToolWireshark
EvidenceDNS Case File

🎯 Aim

Capture and analyse a DNS query and its corresponding response; identify transport protocol, endpoints, ports, transaction ID, flags and DNS record counts.

🧹 Mission 1: Remove Old Clues

Windows
ipconfig /flushdns
Linux
sudo resolvectl flush-caches

On some Linux systems, systemd-resolve --flush-caches may be available. Also clear the browser cache.

🗺️ Capture Mission

1️⃣ Flush

Clear DNS and browser caches.

2️⃣ Capture

Start Wireshark on the active interface.

3️⃣ Trigger

Visit your college website once.

4️⃣ Filter

dns

5️⃣ Pair

Match query and response using the transaction ID.

6️⃣ Preserve

dns-lab.pcapng

⚠️ Capture Note

Encrypted DNS, caching or browser prefetching may affect the trace. Use the instructor-approved setup and record actual observations only.

🕵️ Investigation Tasks

(a) First DNS Query

Record the Wireshark frame number of the first query resolving the college website.

(b) Query Transport

Is the query sent over UDP or TCP?

(c) Matching Response

Record its frame number and whether it uses UDP or TCP.

(d) Query Ports

Record source and destination port numbers.

(e) Response Ports

Record source and destination port numbers.

(f) DNS Server

To what IP address is the query sent?

(g) Transaction ID

Record query and response IDs and explain the purpose of this field.

(h) Flags Length

Determine the length of the DNS flags field.

(i) Query/Response Bit

Identify the bit that determines whether the message is a query or response.

(j) Response-Specific Bits

Identify response-specific flag information visible in the trace and explain its functions.

(k) Query Record Counts

Record Questions, Answers, Authority and Additional counts.

(l) Response Record Counts

Record Questions, Answers, Authority and Additional counts.

🏁 Final Challenge

Reconstruct the DNS Journey
My computer (IP : source port) ↓ DNS Query [Frame ___, ID ___] DNS server (IP : destination port) ↓ DNS Response [Frame ___, ID ___] Resolved result: __________________

Explain how frame numbers, ports, transaction ID and flags prove that the packets belong to one DNS conversation.

❓ Viva Questions

  1. Why flush the DNS cache?
  2. Why is a Wireshark frame number not part of the packet header?
  3. Why does DNS commonly use UDP?
  4. When can DNS use TCP?
  5. Why are ports reversed in the response?
  6. What is the purpose of the transaction ID?
  7. What does the QR bit indicate?
  8. What information is stored in the DNS flags field?
  9. What is the difference between question and answer records?
  10. Why may a response contain authority or additional records?
