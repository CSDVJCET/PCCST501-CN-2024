Application Layer & Peer-to-Peer Paradigms

Prescribed References: Behrouz A. Forouzan, Computer Networks: A Top-Down Approach (Chapters 1 & 2) • 6 Contact Hours

1. Overview of the Internet & Protocol Layering

The Internet architecture is fundamentally partitioned into the Network Edge (end-systems, hosts, servers) and the Network Core (interconnected routers, switches, and packet switches).

TCP/IP 5-Layer Protocol Stack vs. OSI 7-Layer Model
Layer PDU Core Responsibility Standard Protocols
5. Application Message User interaction & high-level network application services HTTP, HTTPS, DNS, SMTP, FTP, BitTorrent
4. Transport Segment / Datagram Process-to-process delivery, port multiplexing, reliability TCP (RFC 793), UDP (RFC 768)
3. Network Datagram / Packet Host-to-host logical addressing & unicast/multicast routing IPv4, IPv6, ICMP, OSPF, RIP, BGP

2. Application-Layer Paradigms

Client-Server Architecture
  • Centralized, always-on server with fixed, well-known IP address.
  • Clients initiate communication and do not talk directly to other clients.
  • Examples: Web (HTTP/HTTPS), Email (SMTP/IMAP), File Transfer (FTP).
Peer-to-Peer (P2P) Architecture
  • Arbitrary end-systems (peers) communicate directly without central servers.
  • Self-scalability: Each peer brings upload capacity as it downloads.
  • Examples: BitTorrent file swarming, Blockchain, VoIP (Skype P2P).

3. World Wide Web & HTTP

HTTP (Hypertext Transfer Protocol) operates over TCP Port 80 (or Port 443 with TLS). It is inherently stateless (no client state maintained between requests; session state managed via Cookies/Tokens).

Persistent vs. Non-Persistent HTTP
  • Non-Persistent HTTP (HTTP/1.0): Each referenced object requires a separate TCP connection ($2 \times RTT + \text{Transmission Time}$ per object).
  • Persistent HTTP (HTTP/1.1): Reuses a single established TCP connection for multiple objects with pipelining.
  • HTTP/2: Multiplexes concurrent requests in binary frames over a single TCP stream.
Hands-On Code: Simple Python HTTP Server
assets/handson_code/module1/http_web_server.py 
import socket, threading

def handle_client(client_sock):
    request = client_sock.recv(1024).decode('utf-8')
    response_body = "<html><body><h1>VJCET PCCST501 HTTP Server</h1></body></html>"
    response = f"HTTP/1.1 200 OK\r\nContent-Type: text/html\r\nContent-Length: {len(response_body)}\r\n\r\n{response_body}"
    client_sock.sendall(response.encode('utf-8'))
    client_sock.close()

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.bind(('127.0.0.1', 8080))
server.listen(5)
print("[*] HTTP Server running on http://127.0.0.1:8080")

4. Domain Name System (DNS) & BitTorrent

DNS maps human-readable hostnames to IP addresses using UDP Port 53. It employs a decentralized hierarchical tree: Root Servers → Top-Level Domain (TLD) Servers → Authoritative DNS Servers.

BitTorrent Protocol: Uses a .torrent file and central Tracker to organize peers into a swarm. Employs Rarest-First piece selection and Tit-for-Tat choking with periodic Optimistic Unchoking.
